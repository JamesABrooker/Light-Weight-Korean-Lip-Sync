## 2026-10-11: Added LRS3 Dataset (English Dataset)

My original plan was to use LRS2 as the English dataset, since that is what Wav2Lip was trained and
evaluated on. However, LRS2 requires an institutional licence agreement with the BBC, which would take
weeks to get signed - not viable with one week left. The English set only has one job in my design:
checking whether Korean fine-tuning degrades English performance. Since that compares the same clips
before and after fine-tuning, any fixed English set works, so I have switched to LRS3, which shares
LRS2's in-the-wild domain and 25 fps frame rate.

The official LRS3 distribution has been discontinued, so I am using a verified Hugging Face mirror
(TheNHz/ellipsis-lrs3-raw). I first tried the test split, but it turned out to only contain 96x96
grayscale mouth crops, which Wav2Lip can't use. Instead, I wrote fetch_lrs3_eval.py to stream the
trainval split and take the first clip from each of the first 100 videos, giving 100 RGB 224x224
face-track clips at 25 fps from 100 different speakers. Wav2Lip never saw LRS3 during training, so
this is still a fair test. The clip IDs are committed in data/lrs3_eval_ids.txt so the baseline and
fine-tuned evaluations use exactly the same clips. The clips themselves are not committed, as the
underlying TED content is non-commercial / no-derivatives.

## 2026-10-11: Completed Audio Pipeline

While reviewing audio_preprocessing.py, I found a bug that would have invalidated my results. My
mel normalisation was scaling to [0, 1], but Wav2Lip actually uses symmetric normalisation to [-4, 4].
The frozen SyncNet expert would have received inputs on the wrong scale, making every LSE-D/LSE-C
score meaningless. My hparams check didn't catch it because it compared my values against a dict I
had written myself.

To properly verify the pipeline, I generated golden mel-spectrograms using Wav2Lip's own audio.py
(in a separate Python 3.10 / librosa 0.9.2 environment, as its code no longer runs on newer librosa),
and wrote parity tests comparing my output against them on one Korean and one English clip. All tests
pass, and a side-by-side spot-check plot shows identical spectrograms (80x257). The full run processed
772/772 KMSAV clips and 100/100 LRS3 clips with no failures.

Two other findings came out of this. First, the KMSAV cropped clips are already 25 fps, not 30, so I
am dropping my planned change to 30 fps - it would have misaligned the expert's 5-frame / 0.2 s audio
window anyway. Second, KMSAV stores audio as separate .wav files next to silent .mp4s, so the pipeline
now reads those directly, and uses ffmpeg to decode any video containers.

My next step is building the Wav2Lip dataset layout and filelists, then running the baseline evaluation.
