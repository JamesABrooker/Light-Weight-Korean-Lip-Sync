## 2026-10-17: Pretrained Wav2Lip and Sync Expert Loaded

To begin M2, I needed the pretrained Wav2Lip generator and the frozen sync expert. The current
Wav2Lip README links to newer "SD" model exports rather than the original release, so to ensure
my baseline matches the model from the paper, I downloaded the original wav2lip.pth,
wav2lip_gan.pth and lipsync_expert.pth from the Nekochu/Wav2Lip Hugging Face mirror, plus the
S3FD face detector. The weights are kept out of git (several hundred MB each, non-commercial
licence), with the download command recorded in the README instead.

Wav2Lip's code relies on the old librosa API, so all Wav2Lip code runs in my separate Python 3.10
environment (librosa 0.9.2, torch 2.5.1), the same one I used to generate the golden mels.

It is important to distinguish two different SyncNets here. The sync expert (lipsync_expert.pth)
is Wav2Lip's own discriminator, which stays frozen and provides the sync loss during fine-tuning.
The evaluation SyncNet (syncnet_python) is Chung & Zisserman's original model, used to compute
LSE-D/LSE-C - that belongs to the metrics issue.

To confirm the expert loads and scores correctly, I wrote check_sync_expert.py. It builds inputs
exactly as Wav2Lip's training code does (5 frames, lower half of the face at 96x96, 16-step mel
window), and compares the sync probability on the correct audio window against a window shifted
by 10 frames. A working expert should score aligned windows clearly higher.

On a Korean clip (54ULzusB3zU/000010, 232 windows):
- mean P_sync aligned: 0.502
- mean P_sync shifted (+10 frames): 0.230
- aligned scored higher in 81.0% of windows

The expert clearly separates in-sync from off-sync Korean audio, so it loads and works correctly.
This is only one clip, so I can't draw conclusions about language bias yet, but I will compare it
against the English result.
