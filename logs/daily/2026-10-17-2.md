## 2026-10-17: Pretrained Wav2Lip and Sync Expert Loaded and Verified

To begin M2, I needed the pretrained Wav2Lip generator and the frozen sync expert. The current
Wav2Lip README links to newer "SD" model exports rather than the original release, so to ensure
my baseline matches the model from the paper, I downloaded the original wav2lip.pth,
wav2lip_gan.pth and lipsync_expert.pth from the Nekochu/Wav2Lip Hugging Face mirror, plus the
S3FD face detector. The weights are kept out of git (several hundred MB each, non-commercial
licence), with the download command recorded in the README instead. All Wav2Lip code runs in my
separate Python 3.10 environment (librosa 0.9.2, torch 2.5.1), as it relies on the old librosa API.

It is important to distinguish two SyncNets. The sync expert (lipsync_expert.pth) is Wav2Lip's
own discriminator, which stays frozen and provides the sync loss during fine-tuning. The
evaluation SyncNet (syncnet_python) is Chung & Zisserman's original model, used to compute
LSE-D/LSE-C in a later issue.

To confirm the expert scores correctly, I wrote check_sync_expert.py. It builds inputs exactly as
Wav2Lip's training code does (5 frames, lower half of the face at 96x96, 16-step mel window) and
compares the sync probability on the correct audio window against a window shifted by 10 frames.

My first English result was surprisingly poor (0.174 aligned vs 0.086 shifted, only 62% of windows
correct) - worse than Korean. The cause was face framing, not language. The expert was trained on
tight S3FD face crops, and only looks at the lower half of the face. LRS3's 224x224 face tracks
are framed much more loosely, so after resizing, the lower half was mostly chin and neck rather
than mouth. I wrote s3fd_crop.py to re-crop clips with S3FD, as Wav2Lip's preprocessing does:

| Clip            | Crop             | Aligned | Shifted | Aligned > shifted |
|-----------------|------------------|---------|---------|-------------------|
| LRS3 (English)  | 224 face track   | 0.174   | 0.086   | 62.1%             |
| LRS3 (English)  | S3FD             | 0.789   | 0.082   | 100%              |
| KMSAV (Korean)  | KMSAV face track | 0.502   | 0.230   | 81.0%             |
| KMSAV (Korean)  | S3FD             | 0.509   | 0.203   | 83.6%             |

With S3FD framing, the expert separates in-sync from off-sync English perfectly, confirming it
loads and scores correctly. Importantly, my KMSAV face-track crops score the same as S3FD crops,
so the KMSAV dataset does not need re-cropping. LRS3, however, must be S3FD-cropped - for the
baseline, inference.py will run its own face detection on LRS3 rather than using a fixed box.

With framing controlled, the Korean clip scores noticeably lower than the English clip
(0.509 vs 0.789). This is only one clip each, with different speakers and recording conditions,
so it isn't evidence yet - but it is exactly the kind of gap the baseline evaluation will measure.
