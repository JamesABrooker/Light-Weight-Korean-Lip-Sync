## 2026-10-12: Building the Wav2Lip Dataset Structure

With the audio pipeline complete, I moved on to the integration issue. I realised that Wav2Lip's
training code doesn't actually read precomputed mel-spectrograms - it expects one folder per utterance
containing the face-crop frames (0.jpg, 1.jpg, ...) and an audio.wav, plus train/val/test filelists,
and computes the mels itself. The audio pipeline work is still valuable, as the parity tests prove the
recipe the dataloader uses is correct, but I needed a separate build step for this layout.

I wrote build_wav2lip_dataset.py to handle this. For each clip in the reviewed manifest, it extracts
the frames, copies the paired wav, and checks that the frame count matches the audio duration at
25 fps (within 2 frames). Every clip is written to a CSV log with its status and a reason if it fails.
The first full run processed all 772 clips with no failures.

The manifest marks every clip as 'train', so the script creates its own split, grouped by video so
that no speaker appears in more than one set. My first attempt split by number of videos, but because
clip counts per video are very uneven, the test set ended up with only 44 clips from 3 speakers - too
thin for my main result. I changed the split to target clip proportions instead (~78/7/15), but one
large video then pushed val up to 145 clips and cut train down to 455.

## 2026-10-13: Final Split Selected

Rather than rebuilding repeatedly, I simulated the split for 200 seeds using the build log and picked
the one closest to my target proportions. Seed 103 gave 597 train / 59 val / 116 test clips, which is
almost exactly on target. I chose the seed purely on split sizes, before running any evaluation, so it
doesn't bias my results. I rebuilt the dataset with this seed, deleted the older logs, and committed the
final build log and filelists.

## 2026-10-17: Integration Complete - Alignment Confirmed

To confirm audio-video alignment, I remuxed the first test clip (54ULzusB3zU/000010) from its extracted
frames and audio.wav back into a video. The 246 frames correspond to 9.84 s at 25 fps, exactly matching
the audio duration, and watching the result confirmed the lip movements match the speech. With all 772
clips processed, the output in Wav2Lip's expected format, and the log committed, the integration issue
is complete.
